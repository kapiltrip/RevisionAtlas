<a id="fifo-core-terms"></a>

### Core terms

The implementation and independent-clock terms below are aligned with the [AMD Embedded FIFO Generator guide](https://docs.amd.com/r/en-US/pg327-emb-fifo-gen/Independent-Clocks-Block-RAM-and-Distributed-RAM) and [Vivado memory-inference guidance](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/Memory-Inference-Capabilities).

| Term | Precise meaning | Hardware / verification meaning |
|---|---|---|
| <a id="term-fifo-core-terms-fifo-first-in-first-out"></a>**FIFO — First-In, First-Out** [↑](#index-term-fifo-core-terms-fifo-first-in-first-out "Back to this term in the alphabetical index") | An ordered storage structure in which the earliest accepted, not-yet-read entry is the next entry returned. | Correctness means no accepted entry is lost, duplicated, or reordered. |
| <a id="term-fifo-core-terms-entry-word"></a>**Entry / word** [↑](#index-term-fifo-core-terms-entry-word "Back to this term in the alphabetical index") | One independently stored payload item. | Its number of bits is the FIFO data width. |
| <a id="term-fifo-core-terms-depth"></a>**Depth** [↑](#index-term-fifo-core-terms-depth "Back to this term in the alphabetical index") | Maximum number of entries the FIFO contract permits to be valid simultaneously. | Depth is capacity, not address width. A depth-16 FIFO needs 4 address bits but may need additional pointer/occupancy state. |
| <a id="term-fifo-core-terms-write-pointer-read-pointer"></a>**Write pointer / read pointer** [↑](#index-term-fifo-core-terms-write-pointer-read-pointer "Back to this term in the alphabetical index") | State identifying the next memory location to write and the next valid location to read. | A pointer advances only when its operation is accepted; request alone is insufficient. |
| <a id="term-fifo-core-terms-occupancy"></a>**Occupancy** [↑](#index-term-fifo-core-terms-occupancy "Back to this term in the alphabetical index") | Number of valid unread entries: accepted writes minus accepted reads since reset, within the FIFO’s boundary policy. | `empty` corresponds to zero occupancy and `full` to capacity in a counter-based synchronous FIFO. |
| <a id="term-fifo-core-terms-request-accepted-operation"></a>**Request / accepted operation** [↑](#index-term-fifo-core-terms-request-accepted-operation "Back to this term in the alphabetical index") | A request expresses intent; an operation is accepted only when the FIFO contract permits it, such as `wr_en && !full` or `rd_en && !empty` for a simple policy. | Pointers, occupancy, and the scoreboard change from accepted operations, never blindly from requests. |
| <a id="term-fifo-core-terms-full-empty"></a>**Full / empty** [↑](#index-term-fifo-core-terms-full-empty "Back to this term in the alphabetical index") | Status conditions that prevent capacity overflow or invalid read consumption. | In an asynchronous FIFO, `full` belongs to the write clock domain and `empty` to the read clock domain; AMD states that independent-clock interface/status signals are valid only in their respective domains ([AMD PG327](https://docs.amd.com/r/en-US/pg327-emb-fifo-gen/Understand-Signal-Pipelining-and-Synchronization)). |
| <a id="term-fifo-core-terms-overflow-underflow"></a>**Overflow / underflow** [↑](#index-term-fifo-core-terms-overflow-underflow "Back to this term in the alphabetical index") | Overflow is a rejected write caused by no available capacity; underflow is a rejected read caused by no valid entry. | They are event/status indications, not permission to corrupt pointers or memory. |
| <a id="term-fifo-core-terms-wrap-bit-extended-pointer"></a>**Wrap bit / extended pointer** [↑](#index-term-fifo-core-terms-wrap-bit-extended-pointer "Back to this term in the alphabetical index") | Additional pointer state that records traversal beyond the RAM address range so equal address fields can be distinguished as empty or full. | The RAM uses address bits; flag logic may need one more bit of history. |
| <a id="term-fifo-core-terms-ram-inference"></a>**RAM inference** [↑](#index-term-fifo-core-terms-ram-inference "Back to this term in the alphabetical index") | Synthesis recognition of an HDL memory pattern and mapping it to registers, distributed RAM, block RAM, or UltraRAM under the target/tool rules ([AMD UG901](https://docs.amd.com/r/en-US/ug901-vivado-synthesis/Memory-Inference-Capabilities)). | A behavioral array does not guarantee one physical memory type; coding style, ports, read latency, and attributes influence mapping. |
| <a id="term-fifo-core-terms-standard-read-fwft"></a>**Standard read / FWFT** [↑](#index-term-fifo-core-terms-standard-read-fwft "Back to this term in the alphabetical index") | Standard read produces output in response to an accepted read according to a defined latency. First-word fall-through (FWFT) makes the oldest available word appear without the same explicit read-to-output sequence. | These are different external contracts; the testbench must not assume one while RTL implements the other. |
| <a id="term-fifo-core-terms-synchronous-fifo"></a>**Synchronous FIFO** [↑](#index-term-fifo-core-terms-synchronous-fifo "Back to this term in the alphabetical index") | FIFO whose storage-control state and read/write decisions use one clock. | Pointer comparison and occupancy do not cross clock domains. |
| <a id="term-fifo-core-terms-asynchronous-fifo"></a>**Asynchronous FIFO** [↑](#index-term-fifo-core-terms-asynchronous-fifo "Back to this term in the alphabetical index") | FIFO with independent write and read clocks that have no required frequency or phase relationship. AMD’s implementation uses memory, local counters, binary/Gray conversion, synchronization, and local status logic ([AMD PG327](https://docs.amd.com/r/en-US/pg327-emb-fifo-gen/Independent-Clocks-Block-RAM-and-Distributed-RAM)). | Payload crosses through dual-port memory while control knowledge crosses through synchronized pointer representations. |
| <a id="term-fifo-core-terms-cdc-clock-domain-crossing"></a>**CDC — clock-domain crossing** [↑](#index-term-fifo-core-terms-cdc-clock-domain-crossing "Back to this term in the alphabetical index") | Transfer of information between logic whose sampling clocks have no guaranteed edge relationship. | CDC correctness needs an architecture and constraints; unrelated clocks cannot be made safe by ordinary functional simulation. |
| <a id="term-fifo-core-terms-metastability"></a>**Metastability** [↑](#index-term-fifo-core-terms-metastability "Back to this term in the alphabetical index") | Temporary analog state possible when a receiving flip-flop samples near a data transition and cannot immediately resolve to a legal logic level. | A synchronizer reduces the probability that unresolved metastability propagates; it cannot promise zero probability or make a multi-bit binary bus coherent. |
| <a id="term-fifo-core-terms-synchronizer"></a>**Synchronizer** [↑](#index-term-fifo-core-terms-synchronizer "Back to this term in the alphabetical index") | Destination-clocked register chain or protocol structure used to reduce metastability propagation risk for a qualifying CDC signal. | Each destination domain uses only the synchronized representation; synchronizer latency makes flag release conservative. |
| <a id="term-fifo-core-terms-gray-code"></a>**Gray code** [↑](#index-term-fifo-core-terms-gray-code "Back to this term in the alphabetical index") | Encoding in which adjacent count states differ in only one bit. | Crossing registered Gray pointers reduces the chance that a destination observes an incoherent mixture of several simultaneously changing binary bits; routing skew still needs control. |
| <a id="term-fifo-core-terms-scoreboard-reference-queue"></a>**Scoreboard / reference queue** [↑](#index-term-fifo-core-terms-scoreboard-reference-queue "Back to this term in the alphabetical index") | Testbench model that records every accepted input and compares each accepted output in FIFO order at the documented latency. | It proves ordering and data integrity across boundary cases more effectively than visual waveform inspection alone. |
| <a id="term-fifo-core-terms-invariant"></a>**Invariant** [↑](#index-term-fifo-core-terms-invariant "Back to this term in the alphabetical index") | Property that must remain true for every legal cycle, such as `0 <= occupancy <= depth` or “a rejected operation does not move its pointer.” | Invariants expose failures during long randomized runs and wrap-around, not just named directed examples. |

## Frequency Dividers

[Back to subject index — Frequency Dividers](#index-subject-frequency-dividers) | [Alphabetical term index](#alphabetical-term-index)

[Subject notes](../Frequency%20Dividers/README.md)

<a id="frequency-dividers-core-terms"></a>

### Core terms

The basic frequency and period meanings follow [NIST’s time-and-frequency definitions](https://www.nist.gov/pml/time-and-frequency-division/popular-links/time-frequency-z/time-and-frequency-z-f); the duty-cycle equation follows [Keysight’s measurement definition](https://helpfiles.keysight.com/scopes/FlexDCA-UG/Content/Topics/Oscilloscope-Mode/Time-Measurements/duty_cycle.htm). Divider implementation terms are tied to the vendor documentation in their rows.

| Term | Precise meaning | Physical / RTL meaning |
|---|---|---|
| <a id="term-frequency-dividers-core-terms-periodic-signal"></a>**Periodic signal** [↑](#index-term-frequency-dividers-core-terms-periodic-signal "Back to this term in the alphabetical index") | A waveform for which there is a positive interval $`T`$ such that its pattern repeats: $`x(t+T)=x(t)`$. | Because the input repeats, complete input cycles can be counted and related to a repeating output cycle. |
| <a id="term-frequency-dividers-core-terms-frequency-f"></a>**Frequency (`f`)** [↑](#index-term-frequency-dividers-core-terms-frequency-f "Back to this term in the alphabetical index") | Rate of a repetitive event, measured in hertz; for period $`T`$, $`f=1/T`$ ([NIST](https://www.nist.gov/pml/time-and-frequency-division/popular-links/time-frequency-z/time-and-frequency-z-f)). | Frequency counts completed patterns, not voltage magnitude, bit value, or the number written on a data bus. |
| <a id="term-frequency-dividers-core-terms-period-t"></a>**Period (`T`)** [↑](#index-term-frequency-dividers-core-terms-period-t "Back to this term in the alphabetical index") | Time interval for one complete repetition; it is the reciprocal of frequency ([NIST](https://www.nist.gov/pml/time-and-frequency-division/popular-links/time-frequency-z/time-and-frequency-z-f)). | A divide-by-$`N`$ output needs $`N`$ reference periods per output period: $`T_{out}=N T_{in}`$. |
| <a id="term-frequency-dividers-core-terms-division-ratio-n"></a>**Division ratio (`N`)** [↑](#index-term-frequency-dividers-core-terms-division-ratio-n "Back to this term in the alphabetical index") | Ratio $`N=f_{in}/f_{out}=T_{out}/T_{in}`$. | It specifies output repetition rate, but it does not by itself specify HIGH time or duty cycle. |
| <a id="term-frequency-dividers-core-terms-modulus"></a>**Modulus** [↑](#index-term-frequency-dividers-core-terms-modulus "Back to this term in the alphabetical index") | Number of distinct states in a counter’s repeating state sequence. A modulo-$`N`$ counter returns to its initial state after $`N`$ accepted clock events. | A decoded event from a modulo-$`N`$ sequence can repeat at $`f_{in}/N`$. The chosen output decode determines its pulse width. |
| <a id="term-frequency-dividers-core-terms-duty-cycle"></a>**Duty cycle** [↑](#index-term-frequency-dividers-core-terms-duty-cycle "Back to this term in the alphabetical index") | Fraction of one output period spent HIGH: $`D=t_H/T_{out}\times100\%`$ ([Keysight](https://helpfiles.keysight.com/scopes/FlexDCA-UG/Content/Topics/Oscilloscope-Mode/Time-Measurements/duty_cycle.htm)). | Two outputs can have the same divided frequency and different HIGH/LOW durations. |
| <a id="term-frequency-dividers-core-terms-toggle"></a>**Toggle** [↑](#index-term-frequency-dividers-core-terms-toggle "Back to this term in the alphabetical index") | State transition $`Q^{+}=\overline Q`$ on a selected active edge. TI’s DFF divider example uses complement feedback so Q toggles at every rising edge and completes one cycle every two input cycles ([TI SN74LVC1G80-Q1](https://www.ti.com/lit/ds/symlink/sn74lvc1g80-q1.pdf)). | A stored bit needs two toggles—LOW→HIGH and HIGH→LOW—to return to its starting state, producing divide-by-2. |
| <a id="term-frequency-dividers-core-terms-clock-enable-pulse"></a>**Clock-enable pulse** [↑](#index-term-frequency-dividers-core-terms-clock-enable-pulse "Back to this term in the alphabetical index") | A synchronous, usually one-cycle control event that tells registers when to update while they remain clocked by the original clock. | It slows *activity* without creating another clock tree. A pulse repeating every $`N`$ cycles has event rate $`f_{in}/N`$, but it is not automatically a 50% clock. |
| <a id="term-frequency-dividers-core-terms-divided-generated-clock"></a>**Divided / generated clock** [↑](#index-term-frequency-dividers-core-terms-divided-generated-clock "Back to this term in the alphabetical index") | A periodic signal derived from a reference and used as a clock for other sequential elements. It must be routed and constrained as a clock; Intel documents generated-clock division with `-divide_by` ([Intel Timing Analyzer clock-divider example](https://docs.altera.com/r/docs/683081/22.2/quartus-prime-timing-analyzer-cookbook/basic-clock-divider-using-divide_by)). | It creates a new clock domain/relationship and therefore needs clock-network and STA treatment. |
| <a id="term-frequency-dividers-core-terms-synchronous-divider"></a>**Synchronous divider** [↑](#index-term-frequency-dividers-core-terms-synchronous-divider "Back to this term in the alphabetical index") | Divider whose state flip-flops all sample the same original clock and compute next state together. | Combinational next-state logic decides which bits toggle; there is no stage-to-stage clock ripple. |
| <a id="term-frequency-dividers-core-terms-asynchronous-ripple-divider"></a>**Asynchronous / ripple divider** [↑](#index-term-frequency-dividers-core-terms-asynchronous-ripple-divider "Back to this term in the alphabetical index") | Divider in which one flip-flop output clocks a later flip-flop. | State bits change after accumulated clock-to-Q delays rather than at one common edge. Intel recommends avoiding ripple counters in FPGA logic ([Intel ripple-counter guidance](https://docs.altera.com/r/docs/683323/18.1/intel-quartus-prime-standard-edition-user-guide-design-recommendations/avoid-ripple-counters)). |
| <a id="term-frequency-dividers-core-terms-integer-divider"></a>**Integer divider** [↑](#index-term-frequency-dividers-core-terms-integer-divider "Back to this term in the alphabetical index") | Divider whose output period spans an integer number of reference periods, such as divide-by-3 or divide-by-5. | A rising-edge counter can directly represent its repeating sequence, although odd ratios need extra design for 50% duty. |
| <a id="term-frequency-dividers-core-terms-fractional-divider"></a>**Fractional divider** [↑](#index-term-frequency-dividers-core-terms-fractional-divider "Back to this term in the alphabetical index") | Divider with a non-integer ratio, such as 1.5 or 2.5, usually implemented through alternating intervals, phase techniques, or both clock edges. | Not every output edge can remain an integer number of rising-edge periods apart. |
| <a id="term-frequency-dividers-core-terms-dual-edge-operation"></a>**Dual-edge operation** [↑](#index-term-frequency-dividers-core-terms-dual-edge-operation "Back to this term in the alphabetical index") | Deliberate use of both rising and falling reference edges. Dedicated FPGA primitives such as ODDR are designed for opposite-edge output behavior ([AMD ODDR documentation](https://docs.amd.com/r/2020.2-English/ug953-vivado-7series-libraries/ODDR)). | It provides half-period edge placement; it is different from writing an ordinary fabric register in an unsupported two-edge `always` block. |

| Term | Precise meaning | Physical / design meaning |
|---|---|---|
| <a id="term-mosfet-and-cmos-core-terms-mos-metaloxidesemiconductor"></a>**MOS — metal–oxide–semiconductor** [↑](#index-term-mosfet-and-cmos-core-terms-mos-metaloxidesemiconductor "Back to this term in the alphabetical index") | A gate/conductor, insulating oxide, and semiconductor stack whose surface charge is controlled electrostatically. | Ideally the gate controls the surface through electric field without steady DC current through the oxide. |
| <a id="term-mosfet-and-cmos-core-terms-mos-capacitor"></a>**MOS capacitor** [↑](#index-term-mosfet-and-cmos-core-terms-mos-capacitor "Back to this term in the alphabetical index") | Two-terminal MOS structure used to study gate voltage, oxide field, semiconductor charge, and surface potential ([MIT MOS Capacitors I](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2009/resources/mit6_012f09_lec09/)). | It is the electrostatic core of the MOSFET before source and drain current are added. |
| <a id="term-mosfet-and-cmos-core-terms-work-function"></a>**Work function** [↑](#index-term-mosfet-and-cmos-core-terms-work-function "Back to this term in the alphabetical index") | Energy from a material’s Fermi level to the vacuum level. | A metal–semiconductor work-function difference shifts the voltage needed for flat band. |
| <a id="term-mosfet-and-cmos-core-terms-accumulation-depletion-inversion"></a>**Accumulation / depletion / inversion** [↑](#index-term-mosfet-and-cmos-core-terms-accumulation-depletion-inversion "Back to this term in the alphabetical index") | Surface regimes in which majority carriers increase, mobile majority carriers are repelled leaving ionized dopants, or minority carriers form a surface layer of opposite conductivity ([MIT MOS Capacitors I](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2009/resources/mit6_012f09_lec09/)). | These names describe *which charge exists at the semiconductor surface*, not three arbitrary curve regions. |
| <a id="term-mosfet-and-cmos-core-terms-surface-potential-psi-s"></a>**Surface potential (`\psi_s`)** [↑](#index-term-mosfet-and-cmos-core-terms-surface-potential-psi-s "Back to this term in the alphabetical index") | Electrostatic potential difference between the semiconductor surface and neutral bulk. | It measures band bending and controls depletion/inversion charge. |
| <a id="term-mosfet-and-cmos-core-terms-flat-band-voltage-v-fb"></a>**Flat-band voltage (`V_FB`)** [↑](#index-term-mosfet-and-cmos-core-terms-flat-band-voltage-v-fb "Back to this term in the alphabetical index") | Gate voltage that makes semiconductor bands flat, cancelling work-function and oxide/interface-charge offsets. | Flat band means no semiconductor band bending; it does not necessarily mean zero applied gate voltage. |
| <a id="term-mosfet-and-cmos-core-terms-threshold-voltage-v-t"></a>**Threshold voltage (`V_T`)** [↑](#index-term-mosfet-and-cmos-core-terms-threshold-voltage-v-t "Back to this term in the alphabetical index") | Gate-voltage reference at which strong inversion/channel formation is conventionally reached under stated body and drain conditions ([MIT MOS Capacitors I](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2009/resources/mit6_012f09_lec09/)). | It marks the transition to useful inversion conduction in the long-channel model; it is not a perfect physical on/off step. |
| <a id="term-mosfet-and-cmos-core-terms-mosfet"></a>**MOSFET** [↑](#index-term-mosfet-and-cmos-core-terms-mosfet "Back to this term in the alphabetical index") | Field-effect transistor in which gate-controlled surface charge forms or modulates a channel between source and drain. | Gate voltage controls channel current while the insulated gate ideally draws negligible DC current. |
| <a id="term-mosfet-and-cmos-core-terms-cutoff-triode-saturation"></a>**Cutoff / triode / saturation** [↑](#index-term-mosfet-and-cmos-core-terms-cutoff-triode-saturation "Back to this term in the alphabetical index") | Long-channel operating regions distinguished by inversion and channel voltage: no strong channel, channel along the full length, or drain-end pinch-off. MIT’s MOSFET lecture sequence develops these regions and current models ([MIT 6.012 lecture notes](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2009/pages/lecture-notes/)). | “Saturation” means current is first-order less dependent on drain voltage after pinch-off; it does not mean maximum possible current in every sense. |
| <a id="term-mosfet-and-cmos-core-terms-overdrive-voltage-v-ov"></a>**Overdrive voltage (`V_OV`)** [↑](#index-term-mosfet-and-cmos-core-terms-overdrive-voltage-v-ov "Back to this term in the alphabetical index") | Gate voltage beyond threshold, such as `V_GS − V_T` for nMOS under the chosen convention. | It sets inversion strength and the triode/saturation boundary in the square-law model. |
| <a id="term-mosfet-and-cmos-core-terms-transconductance-g-m"></a>**Transconductance (`g_m`)** [↑](#index-term-mosfet-and-cmos-core-terms-transconductance-g-m "Back to this term in the alphabetical index") | Small-signal change in drain current per change in gate-source voltage at a bias point, `g_m = ∂I_D/∂V_GS` ([MIT 6.012 MOSFET model lecture](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2005/1b51ad9a9d359aed058fa62378062eb5_lecture11annotat.pdf)). | It measures how effectively gate voltage controls current, which directly affects gain and speed. |
| <a id="term-mosfet-and-cmos-core-terms-channel-length-modulation-output-resistance-r-o"></a>**Channel-length modulation / output resistance (`r_o`)** [↑](#index-term-mosfet-and-cmos-core-terms-channel-length-modulation-output-resistance-r-o "Back to this term in the alphabetical index") | Drain-side pinch-off movement shortens effective channel as `V_DS` rises, giving nonzero saturation output conductance; `r_o=1/g_o` ([MIT 6.012 MOSFET model lecture](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2005/1b51ad9a9d359aed058fa62378062eb5_lecture11annotat.pdf)). | A saturated MOSFET is a finite-resistance current source, not an ideal one. |
| <a id="term-mosfet-and-cmos-core-terms-body-effect"></a>**Body effect** [↑](#index-term-mosfet-and-cmos-core-terms-body-effect "Back to this term in the alphabetical index") | Threshold change caused by source-to-body bias changing depletion charge. | The body is a fourth terminal; tying it incorrectly changes switching point, current, and delay. |
| <a id="term-mosfet-and-cmos-core-terms-parasitic-capacitance"></a>**Parasitic capacitance** [↑](#index-term-mosfet-and-cmos-core-terms-parasitic-capacitance "Back to this term in the alphabetical index") | Unintended/effective capacitance from gate overlap, channel charge, junctions, interconnect, and load. | Every transition must charge or discharge capacitance, creating delay and dynamic energy cost. |
| <a id="term-mosfet-and-cmos-core-terms-cmos-complementary-mos"></a>**CMOS — complementary MOS** [↑](#index-term-mosfet-and-cmos-core-terms-cmos-complementary-mos "Back to this term in the alphabetical index") | Logic style using complementary nMOS pull-down and pMOS pull-up networks so a valid steady state ideally has no direct supply-to-ground path ([MIT 6.004 CMOS notes](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c3/c3s1/)). | One network establishes LOW and the complementary network establishes HIGH, giving rail-to-rail logic and low ideal static power. |
| <a id="term-mosfet-and-cmos-core-terms-vtc-voltage-transfer-characteristic"></a>**VTC — voltage transfer characteristic** [↑](#index-term-mosfet-and-cmos-core-terms-vtc-voltage-transfer-characteristic "Back to this term in the alphabetical index") | DC relation `V_out(V_in)` of a logic gate. | Its slope and transition location determine logic thresholds, gain, and noise immunity. |
| <a id="term-mosfet-and-cmos-core-terms-switching-threshold-v-m"></a>**Switching threshold (`V_M`)** [↑](#index-term-mosfet-and-cmos-core-terms-switching-threshold-v-m "Back to this term in the alphabetical index") | Special VTC crossing where `V_in=V_out`, often used to summarize inverter balance. | It is one point, not an equality that holds across the curve. Device strengths move it left or right. |
| <a id="term-mosfet-and-cmos-core-terms-noise-margin"></a>**Noise margin** [↑](#index-term-mosfet-and-cmos-core-terms-noise-margin "Back to this term in the alphabetical index") | Allowed DC noise between guaranteed output levels and required input thresholds: `NML=V_IL−V_OL`, `NMH=V_OH−V_IH` ([MIT 6.004 signaling notes](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c2/c2s1/)). | It measures how much unwanted voltage can be added while the next gate still interprets the logic value correctly. |
| <a id="term-mosfet-and-cmos-core-terms-propagation-delay"></a>**Propagation delay** [↑](#index-term-mosfet-and-cmos-core-terms-propagation-delay "Back to this term in the alphabetical index") | Time between a defined input crossing and the corresponding output crossing; `t_p` is commonly the average of `t_PHL` and `t_PLH` ([MIT 6.012 CMOS inverter lecture](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2005/resources/lec14/)). | It is input-to-output response time, distinct from the output’s own rise or fall transition duration. |
| <a id="term-mosfet-and-cmos-core-terms-dynamic-switching-power"></a>**Dynamic switching power** [↑](#index-term-mosfet-and-cmos-core-terms-dynamic-switching-power "Back to this term in the alphabetical index") | Average power associated with repeated charging/discharging of capacitance, commonly `P ≈ α C_L V_DD^2 f` for activity factor `α` under the model ([MIT 6.004 design trade-offs](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c8/c8s1/)). | It grows with switched capacitance, voltage squared, and switching rate. |
| <a id="term-mosfet-and-cmos-core-terms-leakage-short-circuit-power"></a>**Leakage / short-circuit power** [↑](#index-term-mosfet-and-cmos-core-terms-leakage-short-circuit-power "Back to this term in the alphabetical index") | Leakage is steady non-ideal current in nominally non-switching states; short-circuit power occurs during transitions when pull-up and pull-down conduct simultaneously. | “CMOS has zero static power” is an ideal first-order statement, not a modern physical guarantee. |
| <a id="term-mosfet-and-cmos-core-terms-drive-strength-sizing-w-l"></a>**Drive strength / sizing (`W/L`)** [↑](#index-term-mosfet-and-cmos-core-terms-drive-strength-sizing-w-l "Back to this term in the alphabetical index") | Ability of a device/network to source or sink current, influenced by mobility, oxide capacitance, overdrive, and transistor geometry. | Wider devices can reduce effective resistance but increase input/diffusion capacitance and area. |
| <a id="term-mosfet-and-cmos-core-terms-transmission-gate"></a>**Transmission gate** [↑](#index-term-mosfet-and-cmos-core-terms-transmission-gate "Back to this term in the alphabetical index") | Parallel nMOS and pMOS pass devices driven by complementary enables, forming a bidirectional CMOS switch. | nMOS supports a strong LOW and pMOS a strong HIGH, avoiding the first-order single-pass threshold loss. |

### MOS capacitor fundamentals

These meanings follow the electrostatic sequence in [MIT 6.012, MOS Capacitors I](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2009/resources/mit6_012f09_lec09/).

| <a id="term-mosfet-and-cmos-mos-capacitor-fundamentals-electron-affinity-q"></a>**Electron affinity (`qχ`)** [↑](#index-term-mosfet-and-cmos-mos-capacitor-fundamentals-electron-affinity-q "Back to this term in the alphabetical index") | Energy from the semiconductor conduction-band edge to vacuum. | <a id="term-mosfet-and-cmos-mos-capacitor-fundamentals-flat-band"></a>**Flat band** [↑](#index-term-mosfet-and-cmos-mos-capacitor-fundamentals-flat-band "Back to this term in the alphabetical index") | Condition in which the semiconductor bands are spatially flat, so the ideal semiconductor has no surface band bending or space-charge field. |

| <a id="term-mosfet-and-cmos-mos-capacitor-fundamentals-depletion"></a>**Depletion** [↑](#index-term-mosfet-and-cmos-mos-capacitor-fundamentals-depletion "Back to this term in the alphabetical index") | Surface region in which mobile majority carriers are repelled, leaving exposed ionized dopants and a finite space-charge width. |
| <a id="term-mosfet-and-cmos-mos-capacitor-fundamentals-inversion"></a>**Inversion** [↑](#index-term-mosfet-and-cmos-mos-capacitor-fundamentals-inversion "Back to this term in the alphabetical index") | Surface condition in which minority carriers become sufficiently numerous that the surface conductivity type is opposite to the bulk. |
| <a id="term-mosfet-and-cmos-mos-capacitor-fundamentals-surface-potential-s"></a>**Surface potential (`ψ_s`)** [↑](#index-term-mosfet-and-cmos-mos-capacitor-fundamentals-surface-potential-s "Back to this term in the alphabetical index") | Electrostatic potential of the semiconductor surface relative to the neutral bulk; it quantifies band bending and classifies the surface regime. |
| <a id="term-mosfet-and-cmos-mos-capacitor-fundamentals-depletion-width-x-d"></a>**Depletion width (`x_d`)** [↑](#index-term-mosfet-and-cmos-mos-capacitor-fundamentals-depletion-width-x-d "Back to this term in the alphabetical index") | Depth of the space-charge region under the depletion approximation. | <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-equivalent-resistance-rc-model"></a>**Equivalent resistance / RC model** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-equivalent-resistance-rc-model "Back to this term in the alphabetical index") | First-order replacement of the conducting transistor network by a bias-averaged resistance charging/discharging `C_L`. It gives physical delay intuition but is not an exact large-signal MOS solution. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-pass-transistor"></a>**Pass transistor** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-pass-transistor "Back to this term in the alphabetical index") | MOSFET used as a controlled connection rather than a restoring logic gate. A lone nMOS passes strong LOW/weak HIGH; a lone pMOS passes strong HIGH/weak LOW. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-transmission-gate"></a>**Transmission gate** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-transmission-gate "Back to this term in the alphabetical index") | Parallel complementary nMOS/pMOS pass switch with complementary enables, giving bidirectional near-full-swing transfer. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-dynamic-switching-energy-power"></a>**Dynamic switching energy / power** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-dynamic-switching-energy-power "Back to this term in the alphabetical index") | Energy drawn while capacitance is switched; one ideal 0→1 charge draws `C_L V_DD²` from the supply, and repeated activity gives average power proportional to `α C_L V_DD² f`. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-short-circuit-power"></a>**Short-circuit power** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-short-circuit-power "Back to this term in the alphabetical index") | Transition-time power caused by simultaneous pull-up and pull-down conduction when the input passes through the inverter transition region. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-leakage-power"></a>**Leakage power** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-leakage-power "Back to this term in the alphabetical index") | Power from nonzero off-state/junction/gate currents even without intended switching. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-v-il-v-ih-v-ol-v-oh"></a>**`V_IL`, `V_IH`, `V_OL`, `V_OH`** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-v-il-v-ih-v-ol-v-oh "Back to this term in the alphabetical index") | Guaranteed/defined input and output voltage boundaries used to classify valid LOW/HIGH levels. They are not all equal to the inverter switching threshold. |
| <a id="term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-noise-margin-nml-nmh"></a>**Noise margin (`NML`, `NMH`)** [↑](#index-term-mosfet-and-cmos-cmos-switching-delay-power-and-noise-noise-margin-nml-nmh "Back to this term in the alphabetical index") | `NML=V_IL−V_OL` and `NMH=V_OH−V_IH`; the allowable unwanted voltage before one valid output can become an invalid input. |

### CMOS sizing and NAND timing

[Notes for this topic](../MOSFET%20and%20CMOS/05%20CMOS%20Sizing%20and%20NAND%20Timing/README.md)

The sizing and delay trade-offs are cross-checked against the [MIT 6.012 CMOS inverter lecture](https://ocw.mit.edu/courses/6-012-microelectronic-devices-and-circuits-fall-2005/resources/lec14/) and [MIT 6.004 design trade-offs](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2017/pages/c8/c8s1/).

| Term | Meaning |
|---|---|
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-transistor-sizing-w-l"></a>**Transistor sizing (`W/L`)** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-transistor-sizing-w-l "Back to this term in the alphabetical index") | Selection of channel width and length to control current drive, resistance, capacitance, and area. Increasing width usually improves drive but also increases input and diffusion capacitance. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-pull-up-pull-down-network"></a>**Pull-up / pull-down network** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-pull-up-pull-down-network "Back to this term in the alphabetical index") | pMOS network that connects an output toward `V_DD` and nMOS network that connects it toward ground for complementary CMOS logic. |

It sets VTC balance and edge asymmetry. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-series-stack"></a>**Series stack** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-series-stack "Back to this term in the alphabetical index") | Two or more conducting transistors in series. The stack has greater effective resistance and internal capacitance than one equal-sized device, so NAND pull-down devices are commonly widened. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-equivalent-inverter-sizing"></a>**Equivalent inverter sizing** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-equivalent-inverter-sizing "Back to this term in the alphabetical index") | Choosing gate-device widths so a selected pull-up/down path has resistance comparable to a reference inverter. It is a path-based approximation, not proof that every transition becomes identical. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-fan-in"></a>**Fan-in** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-fan-in "Back to this term in the alphabetical index") | Number of logic inputs combined by a gate. More inputs can deepen series stacks and add diffusion/internal-node capacitance. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-fan-out-electrical-load"></a>**Fan-out / electrical load** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-fan-out-electrical-load "Back to this term in the alphabetical index") | Amount of downstream input capacitance and wiring driven by an output. Logical connection count matters only through the actual capacitance and timing environment. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-worst-case-transition"></a>**Worst-case transition** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-worst-case-transition "Back to this term in the alphabetical index") | Input transition and initial internal-node condition producing the largest relevant propagation delay. NAND inputs can have different delays because internal charge depends on which device switches. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-average-current-delay-method"></a>**Average-current delay method** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-average-current-delay-method "Back to this term in the alphabetical index") | Approximation `t≈C_L ΔV/I_avg` using an estimated current over the output swing. Its accuracy depends on selecting the correct region trajectory and current average. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-powerdelay-trade-off"></a>**Power–delay trade-off** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-powerdelay-trade-off "Back to this term in the alphabetical index") | Sizing or voltage changes that improve delay can increase capacitance, switching energy, leakage, or area. Optimization must evaluate both cause and cost. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-pdp-power-delay-product"></a>**PDP — power-delay product** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-pdp-power-delay-product "Back to this term in the alphabetical index") | Product of average power and propagation delay, with dimensions of energy, used as one combined trade-off metric. It does not reveal area or separate leakage/dynamic mechanisms. |
| <a id="term-mosfet-and-cmos-cmos-sizing-and-nand-timing-noise-versus-speed-trade-off"></a>**Noise-versus-speed trade-off** [↑](#index-term-mosfet-and-cmos-cmos-sizing-and-nand-timing-noise-versus-speed-trade-off "Back to this term in the alphabetical index") | Moving strength ratio can shift switching threshold/noise margins while also changing rise/fall delay. A faster edge in one direction can worsen balance or the opposite edge. |

### Core terms

| Term | Precise meaning | Physical / practical meaning |
|---|---|---|
| <a id="term-protocols-core-terms-communication-protocol"></a>**Communication protocol** [↑](#index-term-protocols-core-terms-communication-protocol "Back to this term in the alphabetical index") | An agreed set of electrical, timing, framing, addressing, and response rules that lets endpoints assign the same meaning to signal activity. The NXP I2C specification, for example, defines bus signals, transfer conditions, byte formats, acknowledgment, and arbitration rather than merely naming two wires ([NXP UM10204](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)). | A wire carries voltage; the protocol says when that voltage is data, clock, address, acknowledgment, idle, or an error/termination condition. |
| <a id="term-protocols-core-terms-serial-communication"></a>**Serial communication** [↑](#index-term-protocols-core-terms-serial-communication "Back to this term in the alphabetical index") | Transfer in which a word is represented as an ordered sequence of bits over time rather than one simultaneous conductor per bit. | It reduces pin count but requires framing, bit ordering, and timing recovery or an accompanying clock. |
| <a id="term-protocols-core-terms-synchronous-serial-communication"></a>**Synchronous serial communication** [↑](#index-term-protocols-core-terms-synchronous-serial-communication "Back to this term in the alphabetical index") | Communication in which sampling is referenced to an explicitly transferred or otherwise shared clock. | <a id="term-protocols-core-terms-asynchronous-serial-communication"></a>**Asynchronous serial communication** [↑](#index-term-protocols-core-terms-asynchronous-serial-communication "Back to this term in the alphabetical index") | Communication without a continuously transferred sampling clock; endpoints agree on nominal symbol timing and recover alignment from framing transitions. A UART receiver begins from the START transition and samples within later bit cells ([Microchip UART reception](https://onlinedocs.microchip.com/oxy/GUID-F2693295-804D-4E36-8BA5-0105C1751EA5-en-US-3/GUID-2966F8A6-816E-45CF-87A6-FB4C876E377D.html)). | “Asynchronous” does not mean untimed. Both endpoints still require sufficiently close baud rates. |
| <a id="term-protocols-core-terms-frame"></a>**Frame** [↑](#index-term-protocols-core-terms-frame "Back to this term in the alphabetical index") | A defined sequence that packages payload with timing or control fields such as START, address, parity, acknowledgment, or STOP. Microchip’s common UART `8N1` example contains one START bit, eight data bits, no parity, and one STOP bit ([Microchip USART guide](https://onlinedocs.microchip.com/oxy/GUID-78D70ED6-D060-4984-8F25-B119A2A89ABB-en-US-3/GUID-BA123D56-04C4-40CB-93D5-644DF3FD9C1D.html)). | Framing lets the receiver locate data boundaries and detect some invalid conditions. |
| <a id="term-protocols-core-terms-simplex-half-duplex-full-duplex"></a>**Simplex / half duplex / full duplex** [↑](#index-term-protocols-core-terms-simplex-half-duplex-full-duplex "Back to this term in the alphabetical index") | Simplex carries useful data in one direction; half duplex supports both directions at different times; full duplex supports simultaneous opposite-direction transfer. Microchip documents asynchronous USART with separate RX and TX as full duplex and one-wire operation as half duplex ([Microchip USART guide](https://onlinedocs.microchip.com/oxy/GUID-78D70ED6-D060-4984-8F25-B119A2A89ABB-en-US-3/GUID-BA123D56-04C4-40CB-93D5-644DF3FD9C1D.html)). | Count independent data paths and whether they can be active simultaneously; do not infer duplex only from the protocol name. |
| <a id="term-protocols-core-terms-bit-rate"></a>**Bit rate** [↑](#index-term-protocols-core-terms-bit-rate "Back to this term in the alphabetical index") | Number of bits transmitted per second ([Keysight, “Bits Versus Symbols”](https://helpfiles.keysight.com/scopes/FlexDCA-PG/Content/Topics/Quick-Start/theory_bits_vs_symbols.htm)). | It counts transmitted bits; useful payload throughput can be lower after framing, coding, or protocol overhead. |
| <a id="term-protocols-core-terms-baud-rate"></a>**Baud rate** [↑](#index-term-protocols-core-terms-baud-rate "Back to this term in the alphabetical index") | Number of signaling symbols transmitted per second ([Keysight, “Bits Versus Symbols”](https://helpfiles.keysight.com/scopes/FlexDCA-PG/Content/Topics/Quick-Start/theory_bits_vs_symbols.htm)). | Baud equals bit rate only when each symbol represents one bit, as in ordinary binary NRZ UART; the definitions are not universally interchangeable. |
| <a id="term-protocols-core-terms-electrical-layer-versus-protocol-layer"></a>**Electrical layer versus protocol layer** [↑](#index-term-protocols-core-terms-electrical-layer-versus-protocol-layer "Back to this term in the alphabetical index") | Electrical rules define voltage, current drive, polarity, and physical signaling; protocol rules define timing and meaning. | UART framing can be transported through TTL/CMOS GPIO, RS-232, or RS-485 transceivers, but those electrical interfaces are not alternate names for UART. |

### Core terms

The terms below follow the bus definitions and transaction rules in the [NXP I2C-bus specification, UM10204](https://www.nxp.com/docs/en/user-guide/UM10204.pdf).

| Term | Meaning |
|---|---|
| <a id="term-i2c-core-terms-i2c-inter-integrated-circuit"></a>**I2C — Inter-Integrated Circuit** [↑](#index-term-i2c-core-terms-i2c-inter-integrated-circuit "Back to this term in the alphabetical index") | A synchronous, addressed, shared serial bus whose two bus signals are serial data (`SDA`) and serial clock (`SCL`). “Two-wire” counts these signals, not power and ground. |
| <a id="term-i2c-core-terms-sda-scl"></a>**SDA / SCL** [↑](#index-term-i2c-core-terms-sda-scl "Back to this term in the alphabetical index") | `SDA` carries address, direction, data, and ACK/NACK levels. `SCL` supplies the bit timing. Both normally use open-drain/open-collector behavior with pull-ups. |
| <a id="term-i2c-core-terms-controller-target"></a>**Controller / target** [↑](#index-term-i2c-core-terms-controller-target "Back to this term in the alphabetical index") | A controller initiates a transfer, generates START, normally supplies SCL, addresses a target, and ends or redirects the transfer. A target participates when addressed. These replace the older “master/slave” terms in current NXP wording. |
| <a id="term-i2c-core-terms-open-drain"></a>**Open-drain** [↑](#index-term-i2c-core-terms-open-drain "Back to this term in the alphabetical index") | An output that can actively pull LOW or release the line but does not actively drive HIGH. |
| <a id="term-i2c-core-terms-pull-up-resistor"></a>**Pull-up resistor** [↑](#index-term-i2c-core-terms-pull-up-resistor "Back to this term in the alphabetical index") | The external path that charges a released SDA or SCL line toward HIGH. Together with bus capacitance it determines the rising-edge time and LOW-state current trade-off. |
| <a id="term-i2c-core-terms-start-repeated-start-stop"></a>**START / repeated START / STOP** [↑](#index-term-i2c-core-terms-start-repeated-start-stop "Back to this term in the alphabetical index") | START is SDA HIGH-to-LOW while SCL is HIGH; STOP is SDA LOW-to-HIGH while SCL is HIGH. A repeated START begins another transfer phase without first releasing the bus through STOP. |
| <a id="term-i2c-core-terms-address-phase"></a>**Address phase** [↑](#index-term-i2c-core-terms-address-phase "Back to this term in the alphabetical index") | The initial byte sequence that selects a target and states transfer direction; ordinary 7-bit addressing sends seven address bits followed by the `R/W` bit. |
| <a id="term-i2c-core-terms-ack-nack"></a>**ACK / NACK** [↑](#index-term-i2c-core-terms-ack-nack "Back to this term in the alphabetical index") | During the ninth clock, the byte receiver pulls SDA LOW for ACK or leaves it released for NACK. NACK can mean rejection, no receiver, or normal termination of the final byte in a controller read; it is not a checksum. |
| <a id="term-i2c-core-terms-arbitration"></a>**Arbitration** [↑](#index-term-i2c-core-terms-arbitration "Back to this term in the alphabetical index") | A controller that tries to send released HIGH but observes dominant LOW loses ownership and stops driving. This works because every participant observes the actual wired bus. |
| <a id="term-i2c-core-terms-clock-stretching"></a>**Clock stretching** [↑](#index-term-i2c-core-terms-clock-stretching "Back to this term in the alphabetical index") | A target delays progress by holding SCL LOW after the controller releases it. The controller must wait for the physical line to rise. |

<a id="computer-architecture-risc-and-cisc"></a>

### RISC and CISC

<a id="term-computer-architecture-risc"></a>

#### RISC — favor a regular set of easily composed operations

[↑ Back to term index — RISC](#index-term-computer-architecture-risc)

- **Definition:** RISC is an ISA design approach that emphasizes regular
  instruction formats, register-based computation, and comparatively simple
  operations that software composes into larger tasks. The ratified RV32I base,
  for example, defines four fixed 32-bit core formats and is explicitly a
  load-store architecture: loads and stores access memory while arithmetic
  instructions operate on registers ([RISC-V RV32I specification](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html)).
- **Plain meaning:** Give the hardware a small set of consistent building blocks;
  use several blocks when a program needs a larger operation.
- **Hardware meaning:** Fixed field positions and a limited number of operand
  patterns tend to make instruction boundaries and operands easier to decode.
  The datapath can repeatedly move values through registers and relatively
  uniform execution paths. This helps pipelining, but does not guarantee that
  every instruction takes one cycle.
- **Why it matters:** Regularity can simplify the processor front end, compiler
  instruction selection, verification, and the design of small implementations.
  It can also increase the number of instructions required for a task.
- **Do not confuse it with:** “Few instruction mnemonics.” A modern RISC ISA may
  have many optional scalar, vector, atomic, compressed, and cryptographic
  extensions. The “reduced” idea concerns the simplicity and regularity of the
  base operations, not a permanently tiny instruction manual.
- **Examples:** RISC-V and Arm A64 are RISC-style ISAs. Arm states that A64 uses
  32-bit instructions with fields in consistent positions, while most A64
  instructions operate on registers ([Arm A64 ISA guide](https://developer.arm.com/documentation/102374/0103/Registers-in-AArch64---general-purpose-registers),
  [Arm A64 encoding overview](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/the-a64-isa-and-compilers)).

<a id="term-computer-architecture-cisc"></a>

#### CISC — expose richer operations and operand forms to software

[↑ Back to term index — CISC](#index-term-computer-architecture-cisc)

- **Definition:** CISC is an ISA design approach that exposes relatively rich
  instruction semantics, numerous operand or addressing forms, and often
  variable-length encodings. Intel's x86 ISA is the standard current example;
  Intel's own encoder/decoder documentation specifies x86 instructions as
  1–15-byte values ([Intel XED user guide](https://intelxed.github.io/ref-manual/)).
- **Plain meaning:** Let one architectural instruction request more work or
  describe operands more flexibly.
- **Hardware meaning:** The processor front end must determine instruction
  boundaries and interpret optional prefixes, opcode fields, addressing fields,
  displacements, and immediates. An instruction may also combine a memory access
  with an ALU operation. The implementation is free to break that architectural
  instruction into internal operations.
- **Why it matters:** Rich encodings can reduce static instruction count and can
  preserve excellent code density and backward compatibility, but decoding and
  execution are less uniform.
- **Do not confuse it with:** “One instruction always does an entire high-level
  language statement.” Nor does CISC imply that every instruction is slow or
  microcoded.
- **Example:** Intel 64/IA-32 (x86) is CISC-style. Intel publishes separate
  instruction-format and instruction-reference volumes because the ISA supports
  a broad range of encodings and operations
  ([Intel 64 and IA-32 Software Developer's Manuals](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)).

| <a id="term-static-timing-analysis-timing-path"></a>**Timing path** [↑](#index-term-static-timing-analysis-timing-path "Back to this term in the alphabetical index") | A valid chain from a startpoint, through combinational cell/net arcs, to an endpoint. | <a id="term-static-timing-analysis-setup-time"></a>**Setup time** [↑](#index-term-static-timing-analysis-setup-time "Back to this term in the alphabetical index") | Minimum interval for which capture data must already be stable before the active capture edge; it creates a maximum-delay requirement ([Synopsys STA definition](https://www.synopsys.com/glossary/what-is-static-timing-analysis.html)). | Latest data is dangerous. | <a id="term-static-timing-analysis-clock-to-q-delay-t-cq"></a>**Clock-to-Q delay (`t_cq`)** [↑](#index-term-static-timing-analysis-clock-to-q-delay-t-cq "Back to this term in the alphabetical index") | Delay from the active launch-clock transition at a flip-flop to the resulting valid transition at its Q output. | It belongs to the launched data path even though its cause is a clock edge. | <a id="term-static-timing-analysis-clock-latency"></a>**Clock latency** [↑](#index-term-static-timing-analysis-clock-latency "Back to this term in the alphabetical index") | Delay from a clock definition/source to the clock pin of a sequential element. | Different launch and capture latencies create skew. Equal absolute latency can be large without creating local skew. |
| <a id="term-static-timing-analysis-clock-skew"></a>**Clock skew** [↑](#index-term-static-timing-analysis-clock-skew "Back to this term in the alphabetical index") | Difference between capture- and launch-clock arrival times for a timing relationship. With the [STA notes’ convention](../Static%20Timing%20Analysis/README.md#setup-and-hold-reference-equations), `S = L_C − L_L`. | Positive skew helps setup but hurts hold for the same register-to-register relationship. |
| <a id="term-static-timing-analysis-clock-uncertainty"></a>**Clock uncertainty** [↑](#index-term-static-timing-analysis-clock-uncertainty "Back to this term in the alphabetical index") | Margin used to account for imperfect knowledge of clock-edge timing, including specified jitter and modeling variation. | It reduces usable timing margin; it is not automatically identical to measured jitter. |
| <a id="term-static-timing-analysis-jitter"></a>**Jitter** [↑](#index-term-static-timing-analysis-jitter "Back to this term in the alphabetical index") | Variation of clock-edge position over time relative to an ideal timing reference. | Jitter is a physical/source behavior; uncertainty is the analysis margin applied to cover this and other effects. |
| <a id="term-static-timing-analysis-pvt-corner"></a>**PVT corner** [↑](#index-term-static-timing-analysis-pvt-corner "Back to this term in the alphabetical index") | A selected process, supply-voltage, and temperature condition used to characterize or analyze delays. | Slow/low-voltage/hot is not universally worst for every check; setup and hold need the appropriate early/late combinations. |
| <a id="term-static-timing-analysis-maximum-delay-minimum-delay-analysis"></a>**Maximum-delay / minimum-delay analysis** [↑](#index-term-static-timing-analysis-maximum-delay-minimum-delay-analysis "Back to this term in the alphabetical index") | Maximum-delay analysis checks the latest propagation against setup-like deadlines; minimum-delay analysis checks the earliest propagation against hold-like boundaries. Synopsys notes that STA uses longest and shortest path delays for the two purposes ([Synopsys STA definition](https://www.synopsys.com/glossary/what-is-static-timing-analysis.html)). | “Critical path” must be qualified: the worst late path and the worst early path are different problems. |
| <a id="term-static-timing-analysis-mcmm-multi-corner-multi-mode-analysis"></a>**MCMM — Multi-Corner Multi-Mode analysis** [↑](#index-term-static-timing-analysis-mcmm-multi-corner-multi-mode-analysis "Back to this term in the alphabetical index") | Concurrent timing verification across multiple operating modes and PVT/variation corners; Intel’s Timing Analyzer documentation includes multicorner timing analysis in its core model ([Intel basic concepts](https://www.intel.com/content/www/us/en/docs/programmable/683243/24-1/timing-analysis-basic-concepts.html)). | A design is not signed off because one functional mode at one corner passes. |
| <a id="term-static-timing-analysis-false-path"></a>**False path** [↑](#index-term-static-timing-analysis-false-path "Back to this term in the alphabetical index") | A topological path that cannot or must not be sensitized in the intended operating modes and is therefore excluded only through a justified exception ([Synopsys STA definition](https://www.synopsys.com/glossary/what-is-static-timing-analysis.html)). | An incorrect false-path constraint hides a real requirement; it is not a command for silencing an inconvenient report. |
| <a id="term-static-timing-analysis-multicycle-path"></a>**Multicycle path** [↑](#index-term-static-timing-analysis-multicycle-path "Back to this term in the alphabetical index") | A path whose intended capture relationship allows more than the default one cycle, expressed through paired setup/hold exception reasoning ([Synopsys STA definition](https://www.synopsys.com/glossary/what-is-static-timing-analysis.html)). | The architecture grants extra cycles; the exception does not make slow logic functionally correct by itself. |
| <a id="term-static-timing-analysis-timing-signoff"></a>**Timing signoff** [↑](#index-term-static-timing-analysis-timing-signoff "Back to this term in the alphabetical index") | Final evidence that all intended paths, modes, corners, constraints, and exceptions meet the required timing criteria with an accepted analysis methodology. | Clean slack is meaningful only if clocks, I/O delays, CDC policy, exceptions, libraries, and parasitics are complete. |
